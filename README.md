# OfflineBotProject

# Автономный бортовой чат-бот для авиапассажиров

Проект выполнен в рамках магистерской выпускной квалификационной работы на тему **«Разработка интеллектуального ассистента для сопровождения и информирования клиентов авиакомпании»**.

## О проекте

Проект представляет собой автономное веб-приложение бортового чат-бота для пассажиров авиакомпании. Система предназначена для работы без постоянного подключения к интернету: языковая модель, база данных рейса, локальная база знаний и RAG-индекс размещаются локально на бортовом сервере.

Чат-бот отвечает на вопросы пассажиров о текущем рейсе, воздушном судне, питании на борту, погоде, курсе валют, правилах перевозки багажа, маршрутной сети авиакомпании и городах назначения. Приложение поддерживает русский и английский языки.

В проекте также реализована административная панель для сотрудника авиакомпании. Через неё можно подготовить данные рейса перед вылетом, после чего данные синхронизируются с бортовым сервером и становятся доступны пассажирскому чат-боту во время полёта.

## Основные возможности

- локальный запуск языковой модели Llama 3.1 8B через Ollama;
- работа без обращения к внешним облачным API;
- пассажирский веб-интерфейс чат-бота;
- административная панель для подготовки данных рейса;
- хранение структурированных данных в SQLite;
- синхронизация данных между сервером авиакомпании и бортовым сервером;
- локальная база знаний по городам и правилам авиакомпании;
- RAG-поиск по локальной базе знаний;
- детерминированные обработчики для вопросов, требующих точных ответов;
- поддержка русского и английского языков.

## Архитектура

Приложение состоит из двух логических частей:

1. **Сервер авиакомпании** — используется для заполнения и обновления оперативных данных перед рейсом: номера рейса, маршрута, воздушного судна, времени вылета и прибытия, погоды, курса валют, питания и коммерческих предложений.
2. **Бортовой сервер** — используется пассажирами во время полёта. На нём локально работают база данных, база знаний, RAG-индекс и языковая модель.

Перед вылетом сервер авиакомпании формирует пакет данных рейса, который импортируется на бортовой сервер. После этого приложение может работать автономно.

## Результаты тестирования

Качество работы системы проверялось на тестовом наборе из 200 вопросов: 100 вопросов на русском языке и 100 вопросов на английском языке.

Тестирование проводилось в четыре этапа:

1. базовая Llama 3.1 8B без RAG;
2. базовый RAG;
3. улучшенный RAG;
4. финальная версия системы с детерминированными обработчиками.

Итоговая версия системы показала следующие результаты:

| Метрика | Этап 1 | Этап 4 |
|---|---:|---:|
| Correctness | 60 % | 89,8 % |
| Completeness | 54,8 % | 89,8 % |
| Hallucination | 26 % | 3 % |

Таким образом, добавление локальной базы знаний, RAG-поиска, улучшенного отбора контекста и детерминированных обработчиков позволило существенно повысить правильность и полноту ответов, а также снизить долю галлюцинаций.

## Подготовка к запуску

Для запуска проекта потребуется:

- установленный Docker;
- установленный Docker Compose;
- не менее 8–12 ГБ свободной оперативной памяти;
- свободное место на диске для модели Llama 3.1 8B;
- доступ к интернету при первом скачивании модели Ollama.

## Установка и запуск через Docker

### 1. Склонировать репозиторий и скачать папку /data

```bash
git clone https://github.com/makarles/offlinebotproject.git
```

### 2. Собрать и запустить контейнеры

```bash
docker compose up --build -d
```

После запуска будут подняты два контейнера:

- контейнер приложения;
- контейнер Ollama.

### 3. Скачать языковую модель

Модель нужно скачать один раз после первого запуска контейнера Ollama:

```bash
docker compose exec ollama ollama pull llama3.1:8b
```

Проверить список доступных моделей можно командой:

```bash
docker compose exec ollama ollama list
```

Если модель уже скачана и сохранена в Docker volume, повторно скачивать её не нужно.

### 4. Собрать RAG-индекс

Перед полноценной работой приложения необходимо собрать индекс локальной базы знаний. Это нужно для того, чтобы RAG-поиск мог находить релевантные фрагменты по вопросам пользователя.

Вариант 1 — собрать индекс через переменную окружения при запуске:

```bash
BUILD_RAG_INDEX=1 docker compose up --build -d
```

Для PowerShell:

```powershell
$env:BUILD_RAG_INDEX="1"
docker compose up --build -d
```

Вариант 2 — выполнить команду внутри контейнера приложения:

```bash
docker compose exec app python -m backend.rag.indexer
```

Если в вашей версии проекта скрипт сборки индекса называется иначе, используйте соответствующую команду, например:

```bash
docker compose exec app python -m backend.rag.build_index
```

### 5. Открыть приложение

После запуска приложение будет доступно по адресам:

- пассажирский чат: <http://localhost:8000>
- административная панель: <http://localhost:8500/admin>

## Полезные команды

Посмотреть логи приложения:

```bash
docker compose logs -f app
```

Посмотреть логи Ollama:

```bash
docker compose logs -f ollama
```

Остановить контейнеры:

```bash
docker compose down
```

Пересобрать контейнер приложения без кэша:

```bash
docker compose build --no-cache app
```

Запустить проект заново:

```bash
docker compose up -d
```

## Примечания

- При первом запуске модель Llama 3.1 8B скачивается отдельно в контейнер Ollama.
- Для корректной работы вопросов по базе знаний необходимо собрать RAG-индекс.
- Если приложение не отвечает на вопросы, сначала проверьте, что контейнер Ollama запущен и модель скачана.
- Если изменялись материалы базы знаний, индекс нужно пересобрать.
